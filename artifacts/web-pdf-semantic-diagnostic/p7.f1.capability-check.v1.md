# Independent check of Qwen's heading decisions against the source PDFs (diagnostic, no provider call)

Question: are Qwen's decisions right, judged from the PDFs and not from the Gold labels alone?
Method: pdf.js (the text reader bundled with the VS Code PDF extension), independent of the project parser. Each row gives the text, font size and position on its page. Gold is the frozen reference; here it is only compared with the PDF, never changed.
Limit: visual rendering was not available, so bold can only be inferred from font names and sizes. The sample is the missed headings and false positives listed below, not the whole population.

## False positives checked earlier (see p7.f1.v5.fp-review.v1.md)
Most were Gold-correct: table labels, captions, the front-matter issuer and date, and a numbered provision in body text. The one open case is Form No. 02/05 (a definition conflict).

## Conclusion
- Qwen's decisions are **partly right**. Where the rule is clear in the PDF (captions, table labels, body-text provisions, the cover block), Qwen's exclusions match the PDF.
- Qwen's **errors cluster** in three groups: (1) a title or heading on a navigation page is excluded (034, 064, 060); (2) a title fragment is dropped (049 "and"); (3) a document-type title word is dropped (024 "NGHỊ ĐỊNH").
- Group (1) is consistent with the V5 prompt change. V5 kept the general AT-LOCATION rule but dropped the sentence that the heading opening a navigation region (for example "Contents") operates, and the list of navigation lines. This is a hypothesis to be tested (see the V6 design D0.v2), not a proven cause. Group (2) is a boundary error that also appeared in V4.1.
- Two cases (044, 073) are genuinely debatable, and Gold should not be changed on them without a decision.
- This check is small, so it does not give a rate. It shows that the errors are real and systematic, not random noise.
