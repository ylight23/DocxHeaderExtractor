# P7-F1 V5: region-aware Qwen reasoning (Issue #8) — design, offline

Status: DESIGN ONLY. No protocol is frozen, no provider call is made, and no budget is requested. A protocol freeze and any run need the user's approval.
Written for: the user and reviewers of Issue #7 / #8 who know the V1–V4.2a history.

## 1. Why V5 and not another prompt

The direct line (Issue #7) ended with V4.1 as the best measured arm (binary F1 0.868 / 0.866 over two replicates; precision ≈ 0.80, recall ≈ 0.94–0.95). V4.2a added id-targeted tools and exact-text navigation evidence. It did not change the result: F1 0.865, paired ΔF1 CI [−0.040, +0.032].

The failure is in the reasoning unit, not in the evidence:
- In V4.2a the model received an exact-text match for "1. Introduction" on page 2. The copy on page 5 is followed by body prose, and the page-2 line is followed by another heading. The model still selected it, saying "numbered section heading … at this location." It did not use the evidence on that pattern.
- Each occurrence was judged alone. Whether a line is a heading depends on the region it sits in (table of contents, form header, running furniture). The direct question asked about one line at a time, so the region was never stated.

V5 changes the unit: the model first states what each region of the chunk does, then selects headings inside that statement, in one generation.

## 2. Gate (Issue #8, item 7) and the distance to it

| Metric (24 dev documents, independent binary evaluator) | Target | V4.1 (best measured) |
|---|---:|---:|
| Heading precision | ≥ 0.90 | ≈ 0.80 |
| Heading recall (all Gold positives) | ≥ 0.90 | ≈ 0.95 |
| Resolved coverage | ≥ 0.99 | 1.00 |

Precision is the binding gap: about 60 false positives at V4.1. Of these, 25 are table-of-contents lines in 094 and about 10 are form-title continuations in 087. If those 35 were removed with no loss of true positives, precision would reach about 0.90. No design should be judged on that arithmetic alone, because a change could also add false positives elsewhere or lose true ones.

## 3. Reasoning unit and protocol V5 (proposal)

One request per layout chunk (`P7F1QLayoutPacking`, ≤ 48 issued lines). The chunk is unchanged from V4.1, so the comparison isolates the reasoning unit.

Output JSON (one object), schema as implemented in `P7F1RegionProtocolV5` (protocol `P7_F1_REGION_HEADING_V5`):
- `regions`: an array of spans in reading order. Each item:
  - `from`, `to`: the first and last issued ids of the span; `from` is at or before `to`.
  - `function`: 1 to 300 characters, the model's own words (for example: "table of contents entries with no page numbers", "form identifier and subject lines", "body prose"). No ontology and no E/R/O code.
  - `evidence`: optional. When present, refs, each an issued id, a sourceAlias from the request, or a tool evidenceId; up to the chunk size plus 8. Other keys are rejected (`REGION_KEYS_INVALID`). The first run failed when this key was required and capped at 8 (see status doc).
  - **Coverage (required for COMPLETE):** the spans must cover every issued subject exactly once: the first starts at the first subject, each next span starts right after the previous one ends, and the last ends at the last subject. A response that leaves any subject out, including `regions: []`, is rejected as `REGION_COVERAGE_INCOMPLETE`. Without this, an uncovered subject would be scored negative with no region statement.
- `headings`: an array of selected subjects. Each item has `id`, **`region` (required, the 0-based index of the span that contains the subject)**, `evidenceRefs` (1 to 8 refs; at least one must be the subject's own id, alias, or a tool evidenceId whose result includes it), and `justification` (at most 300 characters).
- `unresolved`: optional, as in V4.1.
- **Tool evidence provenance:** a region or heading that cites a tool evidenceId must find it in the raw tool transcript of that request. The binder rejects the request as `CONTRACT_FAILED` (`REGION_EVIDENCE_NOT_IN_TRANSCRIPT` or `EVIDENCE_ID_NOT_IN_TRANSCRIPT`) otherwise.

Prompt: the system prompt is new (not V4.1's). It asks the model to describe each region's function in its context before choosing headings, and to say so when a region's function is unclear. It keeps V4.1's rule that navigation lines are not selected because they name content elsewhere. The model is free to reason; C# does not classify.

### What C# checks (contract only)
- Root keys, id and alias validity, and the issued set (as V4.1).
- Regions: each `from`/`to` pair is issued, `from` is at or before `to`, spans run in reading order without overlap, and (for COMPLETE) they cover every issued subject with no gap.
- Each heading id is issued, its `region` index exists, and the region's span contains the heading's subject.
- Evidence references exist (tool evidence against the raw transcript, in the binder).

### What C# never does
- It never removes a heading because its region has a particular `function`.
- It never maps `function` to a class, to E/R/O or to a veto. A heading whose region is labelled navigation stays selected or not according to the model's own answer.

## 4. Error propagation (Issue #8, item 3)

A wrong region statement can cause a wrong heading decision, but C# does not turn that into a deletion. Two consequences follow:
- The effect of a region error is measured through the heading score, not through a separate rule.
- Region statements are recorded and audited separately (section 5), so that a region error can be seen even when no heading is affected.

## 5. Gold and what may be measured (Issue #8, item 4)

- Gold is the frozen heading label set. It is not converted into region labels. The earlier suggestion to derive region labels from POS/NEG is withdrawn.
- Primary score: the independent binary heading evaluator on the frozen Gold, unchanged.
- Region quality is not scored against Gold. It is reported as an audit: the share of regions whose `function` is inconsistent with the heading decisions inside them (for example, a region labelled "table of contents" that holds selected headings), plus a visual review sample. Any region-level claim needs a reviewer decision, not a Gold derivation.
- Any Gold change after predictions are seen is post-prediction adjudication. It is reported with before and after scores, and the frozen Gold stays as it was.

## 6. Token and size limits (Issue #8, item 5)

What is known from V4.1: the largest request was 74.8 KB (V4.2a plan) and per-run spend was about USD 0.16–0.17. The design adds region output, so output tokens grow. Offline work to do before any freeze:
- Measure the byte and estimated token size of each V5 request on the 24 documents, and set a hard maximum with a margin.
- Measure response length (the max_tokens cap must not truncate a valid JSON; V4.1 had one FINISH_REASON_LENGTH failure on D032-C3, so the margin matters).
- Add contract fixtures for each rejection path: an unknown id, a region out of reading order, overlapping regions, a heading whose `region` index is wrong, and truncated JSON.

Model context limits are not asserted here. The offline check must read them from the endpoint metadata that the runner already fetches, not from memory.

## 7. Offline test cases (Issue #8, item 5)

Each case is a page-level fixture from the 24 dev documents, checked offline (no API):

| Case | What it tests |
|---|---|
| 094 (RFC 9113, page 2 TOC) | Does the region-first statement mark the TOC as a region, so that its entries are not selected? Failure mode seen in V4.1 and V4.2a. |
| 067 (TOC, already fixed) | The fix must survive the new unit. Regression guard. |
| 049 (finance table) | Table rows must stay out. Regression guard for the family that fell from 34 to 2–6 false positives. |
| 087 (form titles) | Form identifier and subject lines versus the substantive section heading. The Gold decision for 087 is recorded in `p7.f1q.087-gold-review-decision.v1.json` (keep frozen Gold). |
| 028 (revision dates, clause labels) | Unstable across V4.1 replicates; a test of region consistency on the same page. |
| 032 (title continuation) | V4.2a produced 5 new false negatives here. Check whether region-first reasoning keeps the title. |
| 044 (figure list) | V4.2a produced 3 new false negatives. Check the list-of-figures region. |

For each case the offline check verifies the contract, the region spans, and the byte size. The semantic outcome is only known after a run.

## 7b. Preflight on real source (Issue #8, item 4)

`preflight-v5` (P7F1Q) reads the frozen plan and bodies, checks every pin and the largest body, and runs the V5 contract on the real 094 chunk C2 taken from the parser (not a fixture). It reports seven cases: full coverage, two regions with a heading, a navigation-described region whose heading the model still selects, and four rejections (missing regions, a gap in the middle, a span that stops one subject short, truncated JSON). Its output receipt (`P7_F1_REGION_PREFLIGHT_V1`) is written with `providerCalls: 0`. The output bound is a character estimate, not a token count: reasoning counts toward `max_tokens` (32768), and only a real run shows the actual length.
