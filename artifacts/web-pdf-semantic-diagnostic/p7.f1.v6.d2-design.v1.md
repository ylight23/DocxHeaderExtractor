# V6 D2: hierarchical semantic reconciliation (Issue #9), design and capacity evidence

Status: DESIGN AND OFFLINE EVIDENCE ONLY. No freeze, no provider call, no Gold change, no production change. Written for the Issue #9 reviewers and the user.

## 1. Principles (fixed for D2)
1. **Qwen makes every semantic decision.** At every node: local decisions, shard self-review, synthesis, global validation. C# never selects a heading, derives a hierarchy, resolves a conflict or excludes a candidate on content.
2. **C# owns structure only:** the ordered source list and ids, shard boundaries (by position and count), the identity and scope of every reference, evidence checks against what the node was shown, the byte budget of each response, and completeness.
3. **Coverage is explicit.** Every occurrence ends with a state (SELECT, NOT_SELECT or UNRESOLVED). MISSING is reported, never converted to NOT_SELECT.
4. **A summary is orientation, not a verdict.** A node may pass fewer ids upward, but dropping an id from `passUp` removes only its revisability at higher levels. It does not change its decision, and it is not a reason to exclude it. Ids that are UNRESOLVED and ids at a group boundary are passed up by rule, so they cannot be lost.
5. **Context is not evidence of decision.** Overlap lines are read-only context for the neighbouring shard. Only the owner shard decides an occurrence in its local pass; higher nodes may revise any shown id, and every revision names its node and output hash.

## 2. Layers
| Layer | Who decides | Input | Output |
|---|---|---|---|
| L0 local | Qwen | owned occurrences (text, page, layout) plus K context lines on each side | explicit decision for every owned id, with evidence refs shown to the model |
| L0 reconcile (shard self-review) | Qwen | owned occurrences with their L0 decisions | revisions of owned ids; COMPLETE carries the rest |
| Synthesis (L1..Ln) | Qwen | `passUp` of up to G child nodes, boundary windows, structural pair observations (same normalised text at two places) | revisions, parent and continuation references between shown ids, and a `passUp` list |
| Global | Qwen | the root's `passUp` list | final revisions; the document's semantic validation |
| Targeted retrieval | Qwen | a question and a budget of read calls | not implemented in D2 yet; see section 8 |

Relations use only ids that the node was shown. `parentId` and `continuesFromId` are structural references between shown ids. A pair observation is a structural fact (identical normalised text at two places, for example a contents entry and a body heading). It is shown to Qwen; it never becomes a decision.

## 3. Node contract (P7_F1_V6_HIER_NODE_V1)
- Root keys: `protocolVersion`, `nodeId`, `status`, `items`, optional `passUp`. Item keys: `id`, `decision`, `evidenceRefs` (1 to 8, each shown), optional `parentId`, `continuesFromId`.
- **Budget:** the raw bytes of any accepted response are at most `OutputBudgetBytes` (default 16,384, half of a 32,768 budget, the other half reserved for reasoning; see section 7). Larger responses are rejected as `OUTPUT_OVER_BUDGET`, so every accepted output is within the bound by construction.
- **Canonical text:** a `\u` escape is rejected (`ESCAPED_UNICODE_NOT_ALLOWED`), since one ASCII character could otherwise cost six bytes.
- **INCOMPLETE** or any non-COMPLETE status changes nothing for the node. A local node must decide every owned id.
- **COMPLETE synthesis or global node:** unlisted revisable ids keep their decision, and the carry is counted per id. The state records the node that set it and the hash of that node's output.
- Every state stores the decision, the source node, the output hash, the references and the evidence list. The raw store holds every payload and response by SHA-256, and the transcript refers to them.

## 5. Proofs and what they do not prove
- **Proved (by construction and by tests):** the largest accepted node output is at most 16,384 raw bytes; no node accepts an escape sequence; every candidate receives an explicit final state or an explicit MISSING in the report; a revision can only target a shown id; a parent or continuation can only target a shown id; a context-only id cannot be revised.
- **Not proved:** the context limit (T_input + T_output + T_reasoning ≤ T_context) and the endpoint's `max_output_tokens` (a separate limit). The reasoning reserve of 16,384 is an assumption that must be confirmed for the endpoint, or the reasoning must be limited by the endpoint itself.
- **Not proved:** that Qwen uses the evidence it is shown, or that its synthesis is correct. The scripted models show the protocol works, not the model's ability.

## 6. Failure modes handled
| Case | Mechanism | Test |
|---|---|---|
| Heading split across two shards | context windows of K lines; the synthesis node sees both halves and names the continuation | `A_heading_split_across_two_shards_is_joined...` |
| Two same-level headings far apart | the synthesis node sees both and may name a parent; a parent not shown is refused | `A_parent_reference_to_an_id_that_was_not_shown...` |
| Contents entry and body heading with the same text | structural pair observation shown to the synthesis node; the decision is Qwen's | pair observations in the synthesis payload |
| Only the main headings of the whole document | the global node revises only what it was shown | `A_global_node_revises_only_what_it_was_shown...` |
| Incomplete node | rejected whole, nothing changes | `An_INCOMPLETE_node_is_rejected_whole...` |
| Context id revised | refused as not revisable | `A_node_may_not_revise_a_context_only_id` |
| Two requests on the same PDF | same tree, different transcripts, different selections | `Two_different_requests_on_the_same_PDF...` |

## 7. Position sensitivity (Lost in the Middle)
The design adopts the following criterion, based on Liu et al., "Lost in the Middle: How Language Models Use Long Contexts", *Transactions of the Association for Computational Linguistics*, 2024 (citation as supplied by the user; not verified in this session). That study measured question answering over many documents and key-value retrieval, not heading extraction by Qwen. It is therefore a reason to test position sensitivity, not evidence that Qwen will fail at a particular rate.

**Implemented and tested:** the prompt order probe. `PromptOrder` is `NORMAL` (reading order), `REVERSED`, or `SEEDED:n`. The same items, ids and content are permuted. `SensitivityDiff` counts the candidates whose decision, parent, continuation or evidence changed between two runs. Tests show that a deliberately position-sensitive model is detected, a position-insensitive model gives zero differences, and a seeded order is reproducible.

**Not yet implemented:** placing a target heading at the head, middle and tail of each shard and each synthesis prompt, with the other content unchanged, as the design asks. This needs a provider run, and it is not authorised.

**Gate use:** the probe is a required measurement for any provider run of D2. A decision that changes with prompt order is reported as a position-sensitivity failure, not as a semantic error. No threshold is chosen here.

## 8. Targeted retrieval (designed, not implemented)
A retrieval node lets Qwen ask for the source of a specific alias, with the read tools already built (`get_page_text`, `search_document_text`, `read_line_span`). It has its own round budget and its own transcript. A decision that rests on retrieved text cites the retrieval evidence id. A decision that rests only on a summary is marked as such. Retrieval is not implemented in the tree yet, and no evidence of its use exists.
