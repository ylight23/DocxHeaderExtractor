# V6 D1 preflight (Issue #9): measured on the 24 development documents, offline, no provider call

Status: PREFLIGHT ONLY. No freeze, no API call, no Gold change, no production change. Written for the Issue #9 reviewers and the user.

## 1. What was run
- Command: `preflight-v6` in `scripts/P7F1Q` (module `V6Preflight.cs`), over the 24 documents of the frozen Gold set. Source list: `p7.f1.v6.preflight-docs.json` (each PDF resolved by its id; exactly one match each). Per-document JSON: `p7.f1.v6.d1-preflight.v1/<id>.json`. Aggregate: `aggregate.json`. Summary and log beside them.
- Method: the real driver (`P7F1V6Driver`) runs on every document, one decision pack per 48-line chunk, with a scripted honest model (it cites only what it was shown and never calls a tool). Every payload, output and tool body is measured from the transcript and the raw store. A separate census reads every page with paging and completes every partial line with `read_line_span`.
- Sizes are exact UTF-8 bytes of what is sent or returned.
- Tokens: no tokenizer is available here. **Tokens ≤ bytes** holds for UTF-8 text (every token has at least one byte), so bytes are reported as the token upper bound. Nothing is claimed about the real token count.

## 3. Findings that block a freeze
1. **Whole-document reconcile output cannot be shown to fit `max_tokens`.** The worst-case output (one decision per candidate, eight evidence refs, a 300-character note) is above 32,768 bytes in **23 of 24** documents. The only exception is 073. A byte bound is not a token bound, but it is the conservative bound the review asked for, and it fails.
2. **Reading the whole document is not possible in one context.** Reading every page of the largest document is 7.2 MB of tool output. Paging makes this possible in calls, not in context. Any claim that the model reads the whole document must rest on search and selective reads, and the evidence that it actually does so must come from a provider run.
3. **Input size of a whole-document reconcile grows linearly.** At 1.47 MB, the largest document cannot be sent as one request in any context of the size known to exist for this model class. The endpoint's real context limit is not in the metadata used here and must be read from the endpoint before a run.
4. **The segmented strategy is feasible for input, not yet for output.** Segments of 200 candidates keep each request under 64 KB, but the worst-case output of one such segment is 200 × 508 = 101,600 bytes, which is still above 32,768. A provable bound needs **at most 60 candidates per segment** (60 × 508 = 30,480 bytes). That gives roughly four times as many requests as 200 per segment: the largest document would need about 180 segments.
5. **Cross-segment synthesis is not built.** Segmented decisions need a final semantic step by Qwen across the segments. That step is not implemented, and it is the part most likely to change decisions. It is a design question, not a preflight measurement.

## 4. Strategy comparison (review section 3)
| Strategy | Request input | Worst-case output | Verdict |
|---|---|---|---|
| Whole-document reconcile, one request | up to 1.47 MB | up to 5.5 MB | Rejected: output bound fails in 23 of 24 documents, input size unknown against context. |
| Segmented, 200 candidates per request | ≤ 64 KB | 101,600 bytes per segment | Rejected: output bound fails per segment. |
| Segmented, 60 candidates per request | ≈ 20 KB | 30,480 bytes per segment | Provable under the byte bound. Preferred for D2 design, with a Qwen synthesis step still to design. |

C# in every strategy only chunks, records and checks identity. No strategy lets C# choose a heading, derive a hierarchy or resolve a semantic conflict. Every final decision traces back to a Qwen response by its raw hash.

## 6. Decision requested
- Accept the preflight numbers above as the basis for the next design step.
- Choose the reconcile strategy for D2: segmented at 60 candidates is the only option here with a provable output bound. The Qwen synthesis step must then be designed and reviewed before any freeze.
- No freeze and no API call until the segment size, the synthesis step and the endpoint context limit are decided.
