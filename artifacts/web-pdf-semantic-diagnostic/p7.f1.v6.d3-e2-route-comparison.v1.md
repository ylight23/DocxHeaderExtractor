## 3. What the comparison shows
- The two routes have the same parameters, limits and uptime. Their prices differ by a uniform 15%, and `us-east-1` is the more expensive one.
- Under the conservative tier rule (a request is charged at the highest tier its byte count reaches), `alibaba` is cheaper on every bound in `p7.f1.v6.d3-cost-bound.v1.json`. For example, the C1 run bound at a 65,536 completion cap is $0.197 on `alibaba` and $0.226 on `us-east-1`.
- `us-east-1` has higher median latency (956 ms against 676 ms). Latency does not change the protocol, but it changes the wall-clock time of a run.
- The tag `us-east-1` names a region. If the data policy or a residency requirement needs a region, that could decide the choice. Nothing in the E1 response states a data policy for either route, so this cannot be checked from the artifact.

## 4. What the E1 response does not establish (must be settled before the route is locked)
1. Endpoint ID. Neither endpoint has an `id` field. The two rows share a display name. The tag is the only key in the response. The lock must record the tag exactly and, if OpenRouter exposes another identifier, that identifier too.
2. How the price tier is chosen. The metadata lists thresholds at `min_prompt_tokens` but does not say whether the tier is decided per request or per document. The user's statement that Alibaba charges by the input tokens of each request is consistent with the planning rule. It is not verified here against OpenRouter's documentation for the chosen route.
3. Reasoning: the parameter `reasoning` is supported on both routes, but the metadata does not state whether reasoning is on by default, whether its tokens count against `max_tokens`, or how the usage object reports them. This is gate T.
4. Data policy and retention on each route. Not in the response. This is gate S.
5. Fallback. The request must name the chosen provider and turn fallback off (`allow_fallbacks` false, `only` set to the tag). This is a request-body setting, not a metadata field.
6. Timeout. Not in the response.
