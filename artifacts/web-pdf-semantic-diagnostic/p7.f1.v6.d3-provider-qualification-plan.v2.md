Written for: the Issue #9 reviewers and the user, to decide whether gate E can close and whether C1 may be licensed.
Status: PLAN ONLY. No inference call. No freeze. No Gold change. No production change.
Supersedes: `p7.f1.v6.d3-provider-qualification-plan.v1.md` (kept for history).
Baseline: commit 81a1c86. Code state for this revision: the commit that adds this file.

## 1. Changes from v1
- Cost: v1 used the scripted request count and the base price. v2 separates a planning bound from an operating bound, and applies the endpoint's tier prices. The base price understated large requests by about 3.3 times.
- Call count: v1 ignored retrieval. v2 counts the structural maximum: each local and reconcile node is one call, each synthesis or global node is up to rounds + 1 calls.
- Candidate hash: the field encoding was ambiguous when source text contained separators. It is now length-prefixed (UTF-8 byte length, colon, value), with a regression test.
- Pin: `RequirePinned` is a fail-closed option. A run without an expected hash is refused before any model call. The provider runner must set it.
- Gaps: a page that starts beyond the contiguous read prefix is counted per (node, query), including queries of nodes later rejected or stopped.
- Gate E: the endpoint metadata GET has been performed (one request, as approved). It shows two routes with the same display name. The route is not locked.

## 4. Cost bounds (two kinds, not to be confused)
Source: `scripts/P7F1Q/d3_cost_bound.py` produces `p7.f1.v6.d3-cost-bound.v1.json`. It reads the E1 raw response (by SHA) and the preflight artifacts. It makes no call.

**Planning bound** (from scripted counts). Not a guarantee for Qwen. Earlier table in v1 is superseded for USD; the counts remain a lower reference.

**Operating bound** (the runner must enforce this before each request):
- model calls: `local + reconcile + (synthesis + global) × (MaxRetrievalRounds + 1)`, with MaxRetrievalRounds = 2 and zero retries;
- input per call: the internal budget, 131,072 bytes (tokens ≤ bytes, so this bounds tokens);
- completion per call: `max_tokens`, which must be set. Two candidates: 32,768 (16,384 visible plus an assumed 16,384 reasoning reserve, not verified) and 65,536 (the endpoint maximum);
- price: the tier the request's byte count reaches (conservative).

| Step | Document | Shard | Structural max calls | Per-call worst, 32,768 completion | Run bound, 32,768 | Run bound, 65,536 |
|---|---|---:|---:|---:|---:|---:|
| C1 | 073 | 60 | 5 | $0.0262 | $0.131 | $0.197 |
| C2 | 094 | 60 | 175 | $0.0262 | $4.59 | $6.88 |
| C2 | 024 | 60 | 251 | $0.0262 | $6.58 | $9.87 |
| C3 | 028 | 60 | 606 | $0.0262 | $15.89 | $23.83 |

Reading the table:
- The C1 example: 073 has three nodes (local, reconcile, global). With two retrieval rounds on the global node, the calls are 2 + 3 = 5. This is the case raised in review.
- These bounds are pessimistic: every request is assumed to use the full 131,072-byte input and the full completion. They are safe ceilings, not expectations.
- No USD ceiling is chosen here. The C1 ceiling should be proposed after gate E and gate T fix the tier rule and the reasoning reserve. A per-call check must refuse a request whose worst case would exceed the remaining ceiling.

## 5. Protocol snapshot before any inference
The adapter must not choose these. They are frozen, hashed and recorded with each request.
- **System prompt:** none exists for the hierarchical nodes yet. The V6 driver has a system prompt constant, but the hierarchical node contract is different and must not reuse it silently. A new versioned system prompt is required, with its SHA-256.
- **Message roles:** one system message (the frozen prompt), one user message whose content is the exact UTF-8 bytes of the node payload. No other roles. No prior turns.
- **Response contract:** the node response schema (`P7_F1_V6_HIER_NODE_V2`), requested through JSON response format. Tools are not used by the hierarchical nodes.
- **Request parameters:** `temperature` 0; `max_tokens` set explicitly (section 4); reasoning setting explicit and recorded; `provider` object with `only` set to the locked tag, `allow_fallbacks` false, and `require_parameters` true.
- **Hashes recorded per request:** system prompt SHA, payload SHA (already recorded by the raw store), request body SHA, response SHA, usage object.
- **Retries:** zero by default. An identical body may be sent again only for a transport failure with no response, and each retry counts against the call maximum.

## 6. Hard stops (checked before each call, not after)
1. Projected worst case for this call, plus the cost already spent, would exceed the ceiling.
2. Call count would exceed the structural maximum for the step.
3. `RequirePinned` is false, or the candidate hash does not match the pin.
4. The locked provider tag in the response differs from the lock, or fallback is in use.
5. A response with a truncation finish reason, or with reasoning consuming the completion before a visible answer.
6. A missing usage object, or a usage object that cannot be matched to the stored response.
7. INPUT_OVER_BUDGET or OUTPUT_OVER_BUDGET for the canary document. These are reported, not solved by raising the budget.
8. A write to Gold, production code, or the frozen protocol directory.

## 7. Candidate pin and provenance
- `CandidatesSha256` now uses length-prefixed fields and covers layout. It is the value to pin.
- The runner must start with `RequirePinned = true` and an expected hash from a frozen manifest. The expected hash must come from the parser output, not from the run being checked.
- `CandidatesPinned` in the summary reports whether a pin was supplied and matched. It is recorded in every provider run.

## 8. Reporting rules (unchanged, restated)
A protocol result is not a claim that the model read or verified the document. Report separately: ProtocolResolved, EvidenceRefsPresent (each decided occurrence names an evidence reference; it does not mean the cited source was shown in full), PresentedShare, GlobalReviewCoverage, UnpagedSearches, UnreadMatches, SearchGapQueries.
