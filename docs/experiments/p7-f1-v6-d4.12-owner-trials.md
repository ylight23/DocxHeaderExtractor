# P7 F1 V6 direct agent: owner trials D4.11j to D4.12 (frozen 2026-10-13)

Issue #9. This page records how the V6 direct agent changed between the D4.11j owner trial and D4.12s, what each change did, and what the runs scored. The model is qwen/qwen3.7-flash on OpenRouter, routed to provider `alibaba` only (`alibaba/us-east-1` ignored, no fallback). Branch: `qualification/p7-f1-v6-d4-contractfix-clean`.

## The final method (D4.12s)

The reference plan pins this method. It was generated from code commit `ac12670`; the code is unchanged since `d3eab6f`. Generate it with:

```
d411j-plan <repo> <artifact-dir> <document.pdf> layout jsonall geometry unwrap single factsuse reps=1 mainrep2 toolrounds toolfactsanalysis factsv3 nolayout retries=3 repairall
```

- **Arm `TOOLFACTS_ANALYSIS_V3`:** one arm, one request per layout segment, one repetition. Prompt SHA `3c557778…`.
- **Instruction (`mainrep2`, SHA `2d057c62…`), verbatim:**
  > Extract the main headings of the document: the headings that carry its structure (its outline).
  > The result is a list of the document's main headings in which each heading appears once: for each heading, select the lines where the heading itself stands (all lines of a heading that runs over several lines), at the start of the part it names, as its representative. A line that only lists, repeats or points to a heading that stands elsewhere, for example in a table of contents, is not that heading's representative and is not selected.
  > When you are unsure about how a line relates to other lines, use the tools to check that relationship.
  > Do not guess: if the evidence does not settle a line, say that it is unresolved instead of choosing.
- **Request:**
  - Each line is shown as alias, page and text only, with no bbox and no font.
  - The payload carries `documentStyles`, a table of the document's text styles: size, bold, rank and line count, with up to 3 example aliases per style and at most 15 styles.
- **Tools:** 8 tools, definitions SHA `17b846fe…`. The first turn must call `get_line_facts`, which returns layout facts V3; later turns are `tool_choice auto`. Each unit may use 3 tool rounds, and the budget counts all of them.
- **Answer:**
  - Every turn uses `response_format: json_object`.
  - One markdown fence around exactly one JSON object is unwrapped, and the strict parser then reads the object.
  - The answer may carry an optional `analysis` string with no length limit of its own; the 16 KB reply cap still applies.
  - Each decision may carry a `reason` of at most 300 characters.
  - Neither field decides anything.
- **Failure handling:**
  - Transport failures are retried up to 3 times after 5 s. The retriable codes are STREAM_ERROR, STREAM_INCOMPLETE, RATE_LIMITED_NO_RETRY, SERVER_ERROR_NO_RETRY and TRANSPORT_ERROR.
  - A refused answer gets a repair turn: the refused reply plus a message that names the refusal. For COVERAGE_INCOMPLETE, the message lists the missing aliases.
  - Repairs have no limit of their own; the arm's call limit stops a unit that keeps failing.
  - Only a unit's final failure counts toward the early stop.
- **Prompt cache:** two `cache_control: ephemeral` marks, one on the system prompt and one on the payload. This is the default; `nocache` turns it off and `cache3` adds a mark on the last history message.
- **Parallelism:** units run 8 at a time by default (`DHX_V6_PARALLELISM`). Above about 6 concurrent requests in total, the provider began rate-limiting. The trials therefore ran three documents at once with 2 each.

Some prose fields in the plan were inherited from the first D4.11j plan and describe that plan: "5 repetitions per cell", "CONTROL then PREFETCH", "refused answers are never repaired" and "no Gold". The pinned fields above (`failureHandling`, `repetitions.perArmAndSegment`, `arms`, `hideLayoutArm` and others) are what the run uses, and the plan check re-derives them from code.

### What the runs show

- **Tools.** Qwen calls tools almost only when the first turn forces it.
  - In the arms where tools were optional, it made 17 tool calls across 285 units.
  - In the forced arms, it made 1,000 calls across 468 units. Most units made 2 calls, 26 made none (refused or failed before the call) and 99 made 3 to 7.
  - Its decisions follow the typography visible in the request; the facts mostly confirm them.
- **Extra lines.** Most extra lines were table-of-contents entries and table labels in bold at the left margin. Removing layout from the request and adding `documentStyles` (V3) reduced them. The representative-line instruction (mainrep, mainrep2) removed the table-of-contents lines on SRC-029: FP fell from 7–22 to 0–5.
- **Recall.** Recall against the all-heading Gold falls as the instruction narrows to main headings. This is expected and is not a measure of main-heading recall; there is no main-heading Gold.
- **Variance.** Run-to-run variance is as large as most of the effects above. Each cell is one repetition, so no single difference between adjacent rows is established.
- **Completeness.** Retry plus unlimited repairs made the last SRC-029 and SRC-089 runs complete in every unit (12/12, 18/18). Earlier runs lost 1–5 units to stream errors and contract refusals.
- **Owner invitation letter.** This document has no Gold. With layout chunking, page 2 gave the same selection in every run, but page 1 did not. In the GEOMETRY and FACTS arms Qwen did not use the layout facts it was given.

### Speed and cost

| SRC-089, mainrep2 | Cache marks | Cached share of prompt tokens | Cache writes | Cost | Wall time | POSTs | R |
|---|---|---|---|---|---|---|---|
| 3ddb1ee7 (retry1, one repair) | 0 | 21% (provider-side automatic) | 0 | $0.0263 | 531 s | 49 | .754 |
| 4b4b5e47 (retries=3, repairall) | 2 | 47% | 64,397 | $0.0178 | 412 s | 42 | .789 |
| 3851c4a9 (retries=3, repairall) | 3 | 56% | 224,426 | $0.0207 | 446 s | 49 | .772 |

- **The third mark costs more than it saves.** It raised the cached share, but 45% of what it wrote was on a unit's last POST and was never read again. So two marks are the default.
- **The cache comparison is not clean.** The no-cache run also differs in failure handling.
- **Where the time goes.** One POST takes about 42–56 s, and about 80% of completion tokens are reasoning across all runs. Reasoning is the largest remaining speed lever, and it was not tested.
- **OpenRouter response caching is not used.** It hits only on byte-identical requests, so it would hide run-to-run variance.

## Caveats

- These are single runs on three public documents and one private one. They are not a held-out evaluation and do not establish generalization.
- The Gold is all-heading. The final method asks for main headings, so its recall here is not comparable with the all-heading runs.
- The data policy, approved by the owner for these runs:
  - ZDR is false;
  - the waiver is not verified;
  - OpenRouter logging is unknown;
  - `data_collection` is set to allow;
  - the owner's invitation letter was sent unredacted.

  Each run has its own authorization file under `d411/`.

## Reproduce

1. Write the plan and dry-run, on a clean, committed tree:
   ```
   d411j-plan <repo> <artifact-dir> <document.pdf> <options>
   ```
2. Create the authorization draft:
   ```
   d45-authorization-draft <plan> <safe-root> <draft>
   ```
3. Approve it. Only the owner's explicit approval allows this step:
   ```
   d45-approve <draft> <approved> <approved-by> <approval-text> <data-collection> accept-open-items|no
   ```
4. Run the plan:
   ```
   d411j-run <repo> <plan> <plan-sha> <approved> <safe-root> <document.pdf>
   ```
   The safe root must have an ACL restricted to the current user. Each plan SHA can be run once.
5. Re-freeze:
   ```
   python -I tools/p7_f1_v6_d412_freeze.py <repo> <safe-root> <out.json>
   ```
