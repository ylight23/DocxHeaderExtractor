### Test, script, and documentation classification

- Regression and architecture tests prove project boundaries, route reachability, source
  grounding, and compatibility behavior. Evaluation/replay tests are allowed to use the Eval
  project only through explicit test or CLI boundaries.
- Build and audit scripts are operational tooling. `source-tree-hygiene-gate.ps1` checks the
  source-tree invariants and delegates the Phase-1 mechanical/final gates; it does not alter
  source or invoke a provider.
- `docs/architecture/current.md`, this ledger, and the hygiene plan are the canonical current
  architecture records. Accuracy-99, Human Gold, and other historical evidence documents are
  intentionally outside this refactor and were not edited.

### Naming and compatibility decisions

- Product identity remains `DocxHeaderExtractor`; no public product rename is proposed.
- `DocumentProcessing` owns parser/source adapters, authority pipeline implementation, and
  processing/review compatibility. `Application` owns provider-independent orchestration
  contracts. `Infrastructure/AI` owns vendor-specific adapters and transport details. `Eval`
  owns benchmark, replay, calibration, gold, and diagnostic implementations.
- The canonical output terms are proposal/candidate/evidence/validated structure. Existing
  compatibility names are retained only where caller evidence or public API compatibility
  requires them and are recorded as such in the ledger.
- `Pipeline` is limited to production orchestration and authority assembly. Projection,
  review, inference, policy, routing, feature derivation, and evaluation concerns have bounded
  directories with explicit owners; strategy, runtime, and projection helpers are additionally
  grouped under `Pipeline/Strategies`, `Pipeline/Runtime`, and `Pipeline/Projections`.
